# FD-06 — Confirmar, cancelar o cambiar la hora desde el correo

> **Fase:** [Fase 3 — US-04](../Fases/fase-3-us04-respuesta-paciente.md) (origen), [Fase 2 — US-03](../Fases/fase-2-us03-recordatorios.md) · **Feature:** ninguna todavía · **Plan:** [US-02.07](../US/02.07-paciente-reagenda-cancela.md) · **Relacionado:** [ADR-10](../Decisions/ADR-10.md), [ADR-13](../Decisions/ADR-13.md), [ADR-08](../Decisions/ADR-08.md)

**Estado:** Propuesta · **Fecha:** 2026-09-10

**Por qué:** cuando al paciente le llega el recordatorio, tiene que poder confirmar, cancelar o pedir
otro horario sin llamar ni escribirle al profesional. Un correo no hace la acción solo: lleva un
enlace único de esa cita que abre una página donde el paciente decide.

**Qué implica:** confirmar y cancelar podrían ser botones de un clic, pero reagendar siempre necesita
una página, porque hay que mostrarle horarios disponibles para elegir. Por eso se hace todo en una
misma página. La opción de "responder el correo" para que el sistema lo lea se descarta por frágil.
El enlace debe ser seguro (un token firmado, con vencimiento, ligado a esa cita) para que nadie pueda
abrir citas ajenas. El backend ya sabe confirmar, cancelar y reagendar; lo que falta es poder
dispararlo desde esta página pública y cuidar la privacidad (sin RUT ni datos clínicos en la URL).
