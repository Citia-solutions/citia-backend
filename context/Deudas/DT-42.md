# DT-42 · El enlace por cita no verifica identidad: reenviado o mal dirigido, transfiere la capacidad

## Qué pasa

El enlace del recordatorio (`/cita#<token>`) es una **capacidad**: quien lo tenga puede confirmar, cancelar o
pedir otra hora para esa cita. No comprueba quién lo usa. Llega a quien no es si el paciente reenvía el
correo, si el buzón es compartido, o si el correo del paciente está mal escrito ([DT-35](DT-35.md): el
correo no se verifica). Una cita cancelada **no se reabre** ([ADR-04](../Decisions/ADR-04.md)).

## Mitigaciones que sí existen (Fase 3)

- **Datos mínimos** en la página: sin nombre del paciente, RUT, contacto ni `tipoConsulta` (ADR-10 §2, S2).
- **Ventana corta:** el enlace solo sirve antes del `inicio` vigente y mientras la cita esté vigente.
- **Invalidar desde el voucher** (S1): el profesional sube la versión y el enlace anterior responde 404.
- **Rastro:** la bitácora guarda `actor_tipo = paciente` y `actor_id` = id del enlace usado; el voucher
  muestra *"Cancelada por el paciente"* / *"Confirmada por el paciente"* (`canceladaPor`, `confirmadaPor`).
- **Límite de tasa:** 5 acciones por hora por enlace (ADR-10 §10).

## Límite de esas mitigaciones

- **Invalidar no entrega un enlace nuevo.** No hay "copiar enlace" (E4): el paciente recibe la versión
  siguiente solo con el **próximo recordatorio**. Si ya no quedan recordatorios por enviar, se queda sin
  enlace para esa cita.
- **Si el problema es la dirección**, el próximo recordatorio va a la misma dirección equivocada salvo que
  el profesional corrija antes el correo (`PATCH /api/pacientes/:id`, vista *Contacto* del voucher).
- La bitácora dice **con qué enlace** se hizo, no **quién** lo usó.

## Por qué importa

Un tercero puede cancelar una hora real, y el paciente se entera al llegar o al recibir un recordatorio
que ya no le llega (los recordatorios de una cita cancelada se anulan). Cuando exista el historial de
comportamiento (RF-08), además, una confirmación o una cancelación hecha por otro quedan en el historial del
paciente.

## Cómo se cierra

El mismo cierre que [DT-23](DT-23.md) y [DT-35](DT-35.md): **verificar el canal de contacto** (el paciente
demuestra que el correo es suyo). Si hiciera falta más, pedir un segundo factor solo en la acción
destructiva (cancelar), sin tocar confirmar. Se revisa con el primer caso reportado de cancelación por un
tercero.
