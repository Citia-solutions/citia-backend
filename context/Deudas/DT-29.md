# DT-29 · Funcionalidad implementada y no conectada

**Origen:** release 1 de US-02 · [ADR-09](../Decisions/ADR-09.md) · [us06](../Features/us06-dashboard-citas.md)
**Severidad:** 🟡 baja (no es un defecto: es alcance de otra historia) · **Estado:** abierta

## Qué pasa

De las 12 rutas que expone el backend, el frontend consume **2**: el login y la creación de cita.
Las otras 10 funcionan, están probadas y **nadie las llama**:

| Ruta | Consumida |
|------|-----------|
| `POST /api/auth/login` | ✅ |
| `POST /api/citas` | ✅ |
| `POST /api/usuarios` | ❌ |
| `POST /api/pacientes` | ❌ |
| `GET /api/citas/hoy` | ❌ el dashboard del front usa datos de prueba |
| `PATCH /api/citas/:id/confirmar` | ❌ |
| `PATCH /api/citas/:id/cancelar` | ❌ |
| `PATCH /api/citas/:id/asistencia` | ❌ |
| `PATCH /api/citas/:id/inasistencia` | ❌ |
| `PATCH /api/citas/:id/reagendar` | ❌ |
| `PATCH /api/citas/:id` (editar) | ❌ |
| `GET /api/citas/:id/historial` | ❌ |

## Por qué importa

**No es una deuda de diseño ni de calidad: es una diferencia de ritmo entre los dos repos.** Se
anota por dos razones concretas:

1. **Nada de esto está ejercitado por un cliente real.** Los tests cubren la lógica, pero el
   contrato HTTP de esas 10 rutas solo se ha probado a mano. El primer consumidor va a encontrar
   detalles —formas de respuesta, códigos, nombres de campo— que hoy nadie ha mirado.
2. **Evita construir dos veces.** Antes de agregar endpoints nuevos conviene mirar esta lista: puede
   que lo que hace falta ya exista.

Caso más visible: el dashboard. `GET /api/citas/hoy` está listo y el front muestra datos de prueba,
así que **una cita que se guarda correctamente no aparece en la lista**. Se ve como un bug y no lo es.

## Cómo se cierra

**No aquí.** Cada ruta se conecta en la historia de usuario que la necesite; este documento solo
registra que están disponibles. En particular **no se decide en este documento** cómo mapear los
estados que el diseño del dashboard contempla (`recuperada`, `riesgo_alto`) y el backend no conoce:
eso es alcance de la historia que aborde el dashboard, y depende de RF-08.

Ver el lado del frontend en `citia-frontend/context/Deudas/`.
