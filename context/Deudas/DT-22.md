# DT-22 · Sin vínculo entre citas reagendadas

**Origen:** [ADR-04 §2](../Decisions/ADR-04.md) · [us06-dashboard-citas](../Features/us06-dashboard-citas.md)
**Severidad:** 🔴 alta · **Estado:** ✅ **CERRADA** (2026-08-23, release 1)

## Qué pasa
ADR-04 estableció que de un estado terminal no se sale: una cita cancelada no se reabre, se crea
otra. Llevado a reagendar, una cita movida tres veces serían cuatro filas **sin ninguna referencia
entre sí**.

## Por qué importa
El sistema no podría saber que fueron el mismo compromiso. Eso rompe RF-07 (reagendamiento) y deja
a RF-08 sin poder responder —ni siquiera formular— la pregunta clave: *¿reagendar cuatro veces es
buen comportamiento, porque avisó a tiempo, o malo, porque costó cuatro huecos?*

## Cómo se cerró
Release 1 (2026-08-23). `Cita.reagendar()` mueve la cita conservando su id y la devuelve a
`pendiente` —la confirmación anterior era para otra hora—, y la tabla `cambios_cita` guarda el
antes y el después de cada movimiento junto a quién lo hizo.

El conteo de reagendamientos de una cita es ahora una consulta directa, y `GET /api/citas/:id/historial`
lo expone. RF-08 ya tiene de dónde leer.
